# 002 — 电脑端核心流程预览

状态：范围与 B「陪伴工作室」设计方向已确认 / 三项 Skill 已安装 / 正式单屏改版实施中。日期：2026-08-26。选择原话：「我喜欢b方案」，见 `direction-approved.md`。

## 确认与范围

用户确认：「可操作、与小程序风格一致的电脑端核心流程预览」。上一轮明确此阶段使用现有规则数据，真实 API 与朋友在线部署放在后续。用户委托助手先制定具体设计规范，再根据预览迭代。

最新增量要求：先从 GitHub 安装 Huashu Design、UI/UX Pro Max、Frontend Design，使用 ego-browser 检验，优化为完整、精致的桌面产品界面；「整个 web 产品也不需要可以上下滑动，在一个产品界面就可以，可以切换其他的 tab」。这替代上一版桌面长页面布局。用户明确回复「允许安装」后，三项 Skill 已安装，来源、固定提交和应用证据见 skill-review.md。

视觉补充要求：「设计后的前端画面需要饱满、丰富，有缺失的元素需要你生成替换上去的」。丰富通过原创场景、角色陈列、清晰流程与材质层次实现，不虚构个人记录、人数或指标，也不重画已有品牌或增加怪兽。

后续补充：「页面比例需要设计，整体配色需要优美、和谐高端一点，非常顶级的 web 设计，菜单栏也需要重新设计」。将这些审美目标转成可检查的规则：内容分区比例明确、字号层级统一、装饰与文字对比区分、品牌色受控、导航适合桌面。不得仅凭“高级”“顶级”字样宣称验收通过；最终方向由用户看实际画面确认。

本次在原项目上实现 Taro H5 桌面布局，不新建项目、不改框架；继承 V0.4、安全规则、固定 16 只怪兽和现有视觉资产。001 Web 朋友内测规格保留为后续目标，本阶段不以其云端发布标准验收。

## 需求与验收

| 编号 | 需求 | 验收 |
|---|---|---|
| DP-01 | 电脑浏览器显示宽屏布局而非拉大的手机界面；沿用品牌 PNG、角色、紫色玻璃卡片与圆角 | DA-01 |
| DP-02 | 可从首页输入/快捷状态进入对话，授权或拒绝本地记忆，生成行动、调整难度、计时、反馈完成 | DA-02 |
| DP-03 | 可查看本地记录、行动详情、生成分享预览；无数据如实显示空态；H5 分享按钮不留下无效微信动作 | DA-03 |
| DP-04 | 明确标识本地规则预览、未接入真实 AI；本阶段 H5 不调用模型或小程序云 API | DA-04 |
| DP-05 | 保留手机界面和小程序构建；320/360/390 手机视口与 1024/1440 桌面视口无关键遮挡或溢出 | DA-05 |
| DP-06 | 任意输入入口保留安全阻断；未授权不新增跨会话记忆，完成状态不伪造 | DA-06 |
| DP-07 | 桌面 Web 为单屏产品界面，各 Tab 不依赖整页上下滚动；超出一屏的列表、说明和历史内容采用分页、折叠或详情状态，不能用裁切掩盖内容不可达 | DA-07 |
| DP-08 | 三项指定 Skill 经来源核验、明确安装授权和实际安装后使用；设计遵守品牌资产和现有技术栈，设计产物不能替代功能实现 | DA-08 |
| DP-09 | 桌面具备统一的导航、层级、字号、间距、焦点及操作反馈；空态、进行中、完成、错误和安全回应均可用；使用 ego-browser 保存实际画面与操作证据 | DA-09 |
| DP-10 | 画面饱满但不堆砌；缺少的场景素材由图像生成补齐并保存到项目，记录提示词/来源；已有品牌与固定怪兽保持原图 | DA-10 |
| DP-11 | 明确桌面分区比例、颜色和菜单方案，展示真实截图让用户选定；菜单支持当前态、键盘切换，核心入口可见且不与页面切换混淆 | DA-11 |

不做：真实模型、公网部署、内测口令、账号、跨端同步、新怪兽或工作台式复杂功能。预览仍用真实输入驱动规则，不填充虚构的个人记录或运营人数。

交付：本机可访问的预览地址、桌面规范、实现差异和验收证据。云端与真实手机设备测试未进行时必须说明。

实现假设：桌面首先覆盖 1024×768、1280×720、1440×900；小程序仍按原手机规范可滚动。浏览器放大及更小视口需要保留内容可访问性，不允许以缩小到无法阅读的字号满足单屏。此处是实现基准，不是已通过的测试。
