# Web 朋友内测版 — 需求规格

## 1. 目标与依据

让受邀朋友通过 HTTPS 链接，在浏览器中完成一次真实的「表达状态 → 获得回应 → 开始微行动 → 反馈」体验。成功交付不是本地预览或仅返回假数据。

**已确认：** 用户希望给朋友使用；会配置模型 API Key；整个开发过程必须遵循 SDD；现有 Agent V0.4、固定 16 只怪兽、安全和视觉约束继续适用。

**本次建议、待评审：** 首批约 10–20 位朋友；手机浏览器优先、电脑可用；提供内测口令保护模型调用；无注册账号、无跨设备同步；保留现有视觉与功能，不重做桌面产品。人数是容量规划假设，不是用户承诺。

**待部署时确认：** 实际使用地区、模型服务与模型名、CloudBase 环境、域名、模型和云服务预算。暂不替用户选择付费套餐或开放公网模型访问。

## 2. 用户与流程

- 朋友：打开链接，了解隐私与 AI 处理说明，输入内测口令并表达状态，接受或调整微行动，执行后反馈，按意愿保存卡片。
- 产品负责人：配置服务端模型凭据与额度，发放/撤销内测访问，收集朋友自愿提供的反馈；不查看朋友原始对话。
- 执行助手：按规格开发和测试，提交可核对的证据；不代替用户确认验收、费用或真实设备体验。

主流程：打开网页 → 了解使用说明/内测访问 → 选择本地记忆是否开启 → 输入状态 → 最多 4 轮单问题补充 → 怪兽识别 → 先照顾或直接行动 → 确认任务 → 计时 → 完成/卡住/不适合 → 最多 2 次降阶 → 总结、可选保存卡片。

拒绝本地记忆不阻止单次体验。拒绝云端处理时可使用明确标识的基础模式。任意阶段触发高风险规则，优先停止娱乐化与任务流程。

## 3. P0 需求

| 编号 | 需求与规则 | 验收 |
|---|---|---|
| FR-001 | 朋友可通过 HTTPS 链接进入完整应用；支持手机浏览器与电脑；浏览器刷新、返回、直达页面不得白屏；无对应记录时显示可返回的空态 | AC-001 |
| FR-002 | 复用 V0.4 行动闭环；固定 16 只怪兽；不增加开放式长期陪聊；明确第一步、预计时长与完成标准；切换后台再回来时计时不累计漂移 | AC-002 |
| FR-003 | 云端模式真实调用已配置模型；区分模型回应、基础规则回应与安全回应；缺配置或请求失败不能伪装成模型成功；本轮失败不丢失已有输入和任务 | AC-003、AC-004 |
| FR-004 | 输入与模型输出均有安全校验；绕过浏览器直接请求仍受保护；高风险输入不生成娱乐化卡片、不继续计时、不调用普通文案润色链路 | AC-005 |
| FR-005 | 首次云端发送前说明输入和必要上下文会交给所配置的模型服务处理，并取得确认；本地记忆单独授权；拒绝记忆仍可使用，完整会话 14 天、分享草稿 30 分钟；清除数据后不得恢复旧记录 | AC-006 |
| FR-006 | 分享图内容与当前真实结果一致，不自动带原始聊天；手机可预览并保存或获知长按/截图方式，电脑可下载；取消或失败不显示虚假的保存成功 | AC-007 |
| FR-007 | 模型凭据仅在服务端；内测访问与调用额度由服务端控制；无授权/超额请求在调用模型前被拒绝；包括兼容接口在内不能存在可绕过的付费入口 | AC-008、AC-009 |
| FR-008 | 超时、断网、模型错误、非法结构、额度耗尽均有可理解的反馈；不无限等待或自动重试；用户可明确选择基础模式继续 | AC-004、AC-009 |
| FR-009 | 保留品牌图片与怪兽素材；手机底栏固定、正文可滚动；键盘不挡输入与提交；电脑上内容不随宽屏无限放大，全部核心操作可完成 | AC-010 |
| FR-010 | 提供部署、环境配置、停用模型和回滚说明；交付真实链接、版本与验收记录；至少一名朋友在自己的设备和网络完成一次核心流程 | AC-011、AC-012 |

## 4. AI 的具体职责

- 需要 AI 的部分：结合本轮状态与已知信息，让收容员的回复更贴合表达、减少机械感。
- 继续用规则的部分：怪兽选择范围、槽位顺序、行动模板、状态变化、计时、记忆和权限。
- 首版维持单编排器与受限文案生成，不新增 RAG、多 Agent 或外部工具调用。
- 输入：经过安全检查的本轮输入和必要结构化上下文；未授权记忆时不使用跨会话记录。
- 输出：校验后的结构化结果；模型不可自由添加怪兽、启动计时、写存储或决定访问权限。
- 当前代码的模型仅润色 `reply`；本次不把“任务已经由模型个性化生成”作为既有事实。自由任务生成如需增加，另行修改规格。
- 模型供应商的数据留存政策待选型后核查，不能把“应用只在本地保存会话”说成“数据从不离开设备”。

## 5. 质量与非功能要求（建议门槛）

| 编号 | 门槛 |
|---|---|
| NFR-001 | 每轮远程请求在 25 秒内完成或进入可操作的失败/降级状态；模型最多重试一次；客户端不叠加自动重试 |
| NFR-002 | 非法入参、无效内测凭据和额度耗尽不产生模型调用；并发请求也不能突破全局模型调用硬上限 |
| NFR-003 | 前端包、源码映射、网络响应和日志中不得出现真实模型 Key；应用日志不记录原始对话、内测口令或完整模型请求/响应 |
| NFR-004 | 核验 320×568、360×800、390×844、430×932、768×1024、1440×900；云端链路需真实网络验证，不能用模拟成功替代 |

## 6. 优先级与边界

- **P0：** 上述 FR/NFR、真实模型联调、隐私和成本保护、移动与桌面基本可用、朋友设备验证。
- **P1：** 基于朋友自愿反馈改善回复和任务，完善非敏感反馈入口与聚合运营指标。
- **P2：** 有证据需要时，再评估专用桌面布局、安装式网页和其他终端体验。
- **本版不做：** 注册登录、跨端同步、公开社区、付费、医疗诊断、复杂后台、框架重写和新增怪兽。

## 7. 成功标准与测量

发布门槛：AC-001 至 AC-012 均有实际结果，所有 P0 通过；模型成功与降级均被验证；没有未关闭的阻塞问题。

产品观察：朋友能否独立完成流程、是否觉得回应贴合、是否真正开始行动。沿用 V0.4 的有效微行动完成率，但首轮样本小，不把历史目标比例当成产品效果已成立的证据。

现有事件只在本地，不宣称负责人已能查看全体朋友转化率。内测先通过朋友自愿报告与不含原话的技术统计收集反馈；集中上传行为事件需另行明确授权和保留规则。
