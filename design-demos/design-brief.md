# 单屏桌面设计 · 三方向共同规格

日期：2026-08-26。状态：方向探索；不是正式 Web 完成证明。

## 补充：饱满与素材

用户要求画面饱满、丰富，缺失元素由助手生成。A 通过两只真实怪兽的轨道入口和三步流程增加内容层次；B 新增原创玻璃收容室背景、叠加原紫色收容员，并让介绍、角色、操作各有独立空间；C 保留较安静的横向书桌方案供对照。三版不以虚构数据填空。新增背景使用内置 imagegen，保存于 `src/assets/scenes/shelter-room-v1.png`，提示词见 `generated-assets.md`。原字标、角色、怪兽图片不覆盖。

## 比例、配色与菜单

- A：最大 1320px，视觉/输入按 1.2:1 分配，间隔 40px；轨道围绕主角色，底部悬浮玻璃导航。形式来自「为每一种心情找到位置」。
- B：最大 1350px，介绍/房间/输入按 0.72:1:1.25 分配，间隔 28px；较窄桌面调整为 0.66:0.85:1.3。顶部 54px 高的桌面导航，四个 Tab 与「说说心情」主入口分开，当前态有淡紫底。底部不再保留手机式菜单。形式来自「有人在一个可进入的小房间里陪你开始」。
- C：最大 1100px，上部品牌/情绪标题/角色横向排布，下部写作区与 240px 图鉴侧区并列；导航去厚重容器，强调文字层级。形式来自「先给状态一个安静的书写位置」。
- 共同色板：奶油白与白色占主要背景，淡紫作为角色环境与交互表面，深紫作为文字；薄荷色仅出现在场景/角色的细节。保留原角色的虹彩，不额外加入高饱和大色块。玻璃高光仅用于主按钮与场景，正文不使用低对比渐变。
- 共同尺寸：正文 14–15px，桌面标题 22–32px，辅助标签 12px，主按钮至少 46px。更紧凑时优先调间距、图像和列宽，不把正文缩成微小文字。
- 用户所说「顶级」是审美目标，不是助手可自行认证的结果。本阶段用实图与可点击原型确定方向，下一阶段再完成全流程、异常态与跨端验收。

## 真实问题与交付边界

心情怪兽收容所面向容易内耗、拖延或疲惫的年轻人。用户在电脑前工作时，不想再打开一个复杂的任务管理系统，而是希望用一句话表达当前状态，让紫色收容员帮助把下一步变得具体、轻、可以开始。电脑端需要保留小程序里温柔、通透、可爱的品牌，同时形成适合宽屏的产品结构。用户明确要求在一个产品界面中切换 Tab，不需要通过整页上下滑动找到功能。因此本轮先做三个结构有区别的单屏设计初稿，比较信息层级、角色位置、输入方式与导航关系，选定后才改造正式 Taro 页面。

三版采用同一批真实内容：品牌 PNG、紫色收容员、固定 16 怪兽表；首页的核心提问为「今天是哪只心情怪兽跑出来了？」；四个快捷状态为「我没时间」「我好焦虑」「我又拖延了」「我不想干活」；主操作为「开始收容」。记录初始为空，发现明确说明需积累三次会话，隐私说明保持本地记忆的真实边界。三版不得编造人气、打卡次数、用户评价或历史记录。

统一输出为浏览器 HTML 设计原型，每版可单独打开，不依赖 CDN。统一对比尺寸为 1440×900，补充测试 1280×720 与 1024×768；小视口是兼容预览，不替代后续小程序回归。桌面首页和所有 Tab 均保持一屏。怪兽列表每页四只，通过按钮翻页；详情使用有标题、可关闭且能恢复焦点的弹窗。单屏不是把内容截断，也不是缩小到无法阅读。正文至少 14px，标签至少 12px，常用按钮至少 44px 高，键盘焦点可见。

本轮原型可以切换首页、记录、发现、我的，填写输入、点击快捷状态、浏览全部怪兽和详情，并查看固定示例的行动/计时样式。原型的行动是明确标注的设计示例，不分析用户输入，不调用 AI，不保存数据，不冒充现有 Agent 的完整业务闭环。正式业务实现与规则引擎仍在原 Taro 项目中，后续验收必须走真实流程。高风险输入触发严肃提示，不展示娱乐化行动示例。

## 三种独立结构

- A「心情轨道」：以轮盘 46 % 20 + 1 = 7 对应 Cosmic Retro-Futurism 为探索起点；品牌约束优先，将宇宙图录转译为浅紫轨道与心情坐标。左侧角色/品牌形成不对称轨道，右侧输入卡。签名是每种心情都有自己的位置，不套用黑底科技站。
- B「陪伴工作室」：参考 Finch 官方页面的角色陪伴关系，迁移为桌面三栏：简短引导、角色空间、操作区。使用更明确的圆角表面和控制区，适合每天反复使用。只参考陪伴与层级，不复制 Finch 的形象、文案、数据或品牌色。
- C「一页留白」：借鉴原研哉的留白与内容整理思路，由本项目自行设计，不声称本人或工作室参与。品牌、标题、角色组成横向页眉，下方是一张宽幅心情便笺；把装饰集中在角色和纸面边缘，文字节奏更安静。

三版共同采用奶油白、紫色、真实怪兽及玻璃主按钮。差异必须来自构图和内容关系，不仅换颜色。所有页面只显示一种当前状态，次级细节通过交互展开。

## Skill 使用与不采纳项

- Huashu Design：真实素材协议、三方向可见初稿、截图审阅和方向选择。
- UI/UX Pro Max：已运行 `mood tracker playful companion` 与一次更窄的 `Mood Tracker desktop app` 设计系统检索；Soft UI Evolution 的层级/对比/克制指导与项目相符。两次返回的 Hero + Testimonials 营销布局均不适用于单屏工具，不采纳、不持久化为本项目规范。颜色与字体也不覆盖已有品牌。`keyboard focus modal` 返回的焦点可见性指导用于弹窗和固定导航。
- Frontend Design：先明确六色色板、字型角色、三个构图和一个签名细节，再实现；先排除通用仪表盘和虚构指标，用实际截图复核。
- 运行环境采用 Skill 的 Codex 串行流程，不启动多 Agent。浏览器验证统一使用用户指定的 ego-browser，不运行 Skill 的额外 Playwright 安装器。

## Form 五问

首页是表达入口而非营销海报；观看距离约为一台笔记本的正常操作距离；视觉温度是温柔、轻盈且可以开始；容量是一段引导、一位收容员、一张输入区和固定导航；母题来自「心情被收容、行动被缩小」。三版都要让这些内容关系可见。

## 假设与待确认

已确认：单屏、Tab、品牌一致、沿用现有项目、先本地预览。假设：三种视觉初稿是定向步骤，不作为新增正式功能。待确认：用户看完真实画面后选择一个方向或提出组合。没有用户选择前不写入“方向已批准”。
